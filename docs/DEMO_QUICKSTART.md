# 局域网战术遭遇 Demo

首个可玩版本已完成本轮验收。测试、浏览器试玩及既有问题见 [实施记录](DEMO_IMPLEMENTATION.md)。

## 启动

使用 Node.js 22.x、pnpm 10.x，在仓库根目录执行：

```powershell
pnpm install
pnpm demo
```

`pnpm demo` 按 shared → backend → frontend 构建，然后启动同源服务器。已经构建时可运行 `pnpm demo:start`。默认监听所有网卡的 3000 端口，GM 在本机打开 `http://localhost:3000`，其他玩家打开 `http://<主持电脑的局域网 IPv4>:3000`。

主持凭据和房间加入码保存在本机 `.demo/credentials.json`；GM 使用主持凭据登录，向玩家提供加入码。玩家只填写昵称与加入码，再由 GM 分配角色。同一浏览器不同标签页可分别登录，访问令牌不会放入 URL。

仅在 Windows 防火墙实际阻止其他设备访问时，为此局域网进程放行对应端口。可用 `ipconfig` 查看当前网卡 IPv4 地址。

## 隔离数据与配置

存档默认位于 `.demo/demo.db`，不使用 `packages/backend/prisma/dev.db`。不要对 Demo 运行 `db:push` 或 seed。

| 环境变量 | 用途 | 默认值 |
| --- | --- | --- |
| `ELYSIAN_DEMO_DATA_DIR` | 独立存档及凭据目录 | 仓库根目录 `.demo` |
| `ELYSIAN_DEMO_PORT` | 监听端口 | `3000` |
| `ELYSIAN_DEMO_HOST` | 监听网卡 | `0.0.0.0` |
| `ELYSIAN_DEMO_HOST_CREDENTIAL` | 显式设置本次主持凭据 | 启动时生成 |
| `ELYSIAN_DEMO_JOIN_CODE` | 显式设置本次加入码 | 启动时生成 |
| `ELYSIAN_DEMO_ALLOWED_ORIGINS` | 开发环境跨源白名单，逗号分隔 | 同源 |

开发前端可设置 `VITE_SERVER_URL` 连接指定后端，并在后端明确允许该前端来源。生产游玩无需设置跨源地址。

## 基本操作

1. GM 登录、三名玩家加入，GM 分配先锋、游侠、引导者。
2. 玩家默认选中自己的角色，GM 使用“操控实体”切换角色。开始遭遇后，先点动作，再点击高亮的合法目标或移动目的格即可提交；点击角色所在格也可指定移动落点。Esc、地图右键或“取消”退出选择，点击另一动作直接切换。等待和恢复无需目标。最后一个就绪槽提交前不会推进时间。
3. 反应窗口先在 10 秒内接入，再在 60 秒内选择。不同反应按生效 Tick 与优先级处理；等待不恢复资源，须使用“恢复资源”动作。GM 暂停冻结期限，仍可代选反应。
4. 遭遇结束后检查结算保存状态，再重开。刷新页面恢复当前服务器内存对局；重启服务器从开局状态重开，不承诺精确续接中途战斗。

GM 使用裁决台从模板刷怪、调整资源/位置/朝向/状态、切换阵营或接管玩家。“暂停”后可编辑未结算动作的目标、生效 Tick、优先级，并填写裁决原因；“单步结算”推进一个事件 Tick，“下一 Tick 断点”停在下一个 Tick 生效前。取消已开始动作进入收招；已生效结果用“追加修正”处理，原日志保留。怪物由 GM 手动操作，不会自动选择行动。

动作选择时，提示条显示费用、耗时与目标是否合法；键盘可用 Tab 定位、Enter/空格提交。提交后以“多人就绪”状态为准。GM 刷怪和位置调整使用普通状态下选中的格子，不会混入动作目标。若服务仍在运行旧版本，页面会明确提示并保留原点选方式；正常停止并重新启动服务后启用新流程，请勿为更新界面而丢弃尚未结束的对局。

## 隔离回归

```powershell
pnpm test:demo
```

运行器使用临时 SQLite 和当前 TypeScript 源码，并核对开发数据库及 schema 的 SHA-256。失败项和实际验证进度记录在实施记录中。
