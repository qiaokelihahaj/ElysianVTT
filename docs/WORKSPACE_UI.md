# 模块化战术工作台

桌面上进入遭遇后，地图直接铺满整个桌面，页面不再保留顶部工具栏。右上角「☰」菜单集中提供房间信息、模块找回和布局重置。时间轴、实体列表、日志、行动/反应与 GM 工具均为地图上方的独立浮窗，不占用地图布局空间。全部窗口默认自动收起为边缘名称：时间轴在上、行动在下、实体列表在右、日志和主持工具在左。悬停或点击名称展开，图钉可让窗口常驻。宽度至少 1200px 时，实体列表默认尺寸为 500×420px，动作栏与时间轴各高 220px。大厅保持原有入场和选角流程。

## 窗口操作

- 进入遭遇后默认隐藏顶部品牌标题和房间信息，释放 68px 高度给战场。右上角菜单的「房间信息」可展开查看房间、身份和退出入口，再点「收起房间信息」隐藏；大厅仍显示完整标题栏。
- 桌面未固定窗口悬停名称 150ms 后展开，离开 500ms 后收回；快速返回会取消收回。标签也支持点击、Enter 和空格。桌面触屏使用点击名称展开、点击外部收回。
- 拖动标题移动，拖动右下角调整大小。拖动结束按完整窗口到四边的距离更新停靠方向：原方向仍属于最近边时继续保留；多个最近边不含原方向时，参考最后一段实际拖动的方向。例如原来停靠上方，拖至左下角，最后向左移动则收进左边，最后向下移动则收进下边。抵达边界后的空移动不会覆盖最后方向，键盘移动同样适用；缩放不参与拖动方向判断，没有明确方向时沿用稳定的兜底顺序。未固定窗口展开时贴住对应边缘，尺寸限制在可用工作区内。
- 收起名称沿对应边保留窗口的位置：上下标签以展开矩形的横向中心为锚点，左右标签以纵向中心为锚点，左下、右下和中下分别出现在相应位置。标签只在接近时错开避免重叠，按窗口空间位置排列，锚点相同时才按模块顺序排列；靠近角落时限制在轨道安全范围内并避开工作台菜单，空间不足可滚动。左右标签竖排，上下横排，点击恢复保留窗口原有位置和尺寸。
- 点击空心图钉固定在当前展开位置，实心图钉表示已固定；再次点击恢复自动收起。点击窗口会将它置于其他普通窗口前方。
- 标题移动按钮及缩放手柄支持方向键；按住 Shift 每次调整 40px，默认 10px。
- 窗口不再显示装饰编号。行动窗口使用紧凑拖动柄；时间轴保留紧凑表头，显示标题、当前 Tick 和全局状态，浏览工具位于右侧「···」菜单，窗口管理入口位于顶部。图钉、最小化、隐藏控件与内容错开，在 300px 宽的时间轴中仍可操作。
- `−` 立即最小化为边缘名称。已固定窗口保留固定状态，必须点击名称才恢复，悬停不会打开；未固定窗口需鼠标离开再重新悬停，避免原地反复弹出。`×` 连同标签一起隐藏，右上角菜单可找回。
- 菜单找回或时间轴打开主持编辑时，窗口保持展开，直到用户进入后离开，或点击外部。拖动、缩放、输入、键盘操作及使用窗口内操作菜单期间不会自动收起；普通鼠标点击留下的按钮焦点不会永久阻止收起。
- 收起保留内容组件、表单草稿、时间轴缩放和滚动位置，收起内容不可点击或获取键盘焦点。收起行动窗口不取消地图目标选择。展开和收回约 180ms，开启系统「减少动态效果」后取消动画。
- 「恢复默认布局」恢复全部面板的默认位置与可见状态。
- 布局使用本机浏览器 localStorage v3，按 GM、玩家、观察者分别记忆位置、尺寸、隐藏、手动最小化、固定状态和停靠边缘，不保存身份凭据或游戏状态。首次读取 v2 时保留位置、尺寸和隐藏状态，全部设为未固定，旧折叠条改为自动收起标签。悬停收展不写入手动最小化状态，存储不可用时仍可操作。
- 宽度不超过 760px 时，地图、行动、实体列表、时间轴、日志和主持工具按顺序纵向排列，保留手动折叠；右上角菜单可展开并定位面板，选择需要目标的技能后定位到地图。窄屏不显示边缘标签、图钉和拖动/缩放入口，折叠操作不覆盖桌面固定偏好，回到桌面使用保存的浮窗布局。

地图保持主画布；当前没有浏览器跨窗口弹出、拖拽吸附分区或服务端布局同步。

地图底部不再常驻阵营图例和实体数量；棋子保留阵营颜色及悬停说明。当前 Demo 的实体概览由独立「实体列表」窗口提供，替代原行动栏中的「多人就绪」。另一套 HUD 的 `EntityList` 组件不复用于 Demo。

地图不再显示顶部的 TACTICAL MAP、地图名、操控实体下拉框及选中实体生命摘要。点击实体列表中的名称即可选择实体，地图与行动栏同步更新；位置、生命和其他资源统一在列表及详情中查看。地图点选也使用相同的本地选择流程；选择非受控实体仅查看信息，动作栏仍显示无控制权。切换实体会取消尚未提交的目标选择，提交期间暂时禁用切换。桌面地图画布铺满工作区，临时目标提示以浮层显示，不再挤压画布。

## 决策与权限

本人的待决反应出现时，行动/反应面板强制可见、展开并滚动至顶部；此时不能折叠或隐藏，结束后恢复原有布局偏好。GM 可见的待决窗口同样处理。时间轴的编辑入口会展开 GM 工具。玩家不会挂载 GM 工具窗口。

行动栏主提示使用当前权威快照区分选择角色、选择行动、已提交、等待收招、倒下、GM 暂停和反应处理。拥有多个角色时，任一受控角色的待决反应都会提示本人处理；其他角色的反应则显示等待。资源使用生命、韧性、专注、敏捷等中文名称，未知规则包资源保留原名称。反应卡显示角色名，实体和窗口 ID 收在技术详情中，放弃按钮统一使用中文。

主持工具按「实体与场景」「行动与反应」「裁决与历史」分组；从时间轴进入动作编辑时会展开对应分组并定位编辑入口。

通知放在左下方，避开右侧反应入口。成功和普通信息提示自动消退，警告和错误保留手动关闭。布局变化不改变服务端权限、规则、快照或命令协议。

## 独立实体列表

阵营支持自定义名称；「独立」表示实体各自为一方，不把所有独立实体归成一个中立阵营。列表、地图与时间轴使用同一稳定配色，颜色仅辅助识别，名称或简称用于区分。旧 Demo 的 PLAYERS/ENEMIES 仍可读取，控制权不由这两个名称决定。

敌友关系相对于当前选中实体显示。同阵营视为同方，不同阵营默认关系未设置；GM 可设置对称的同盟、中立或敌对关系，也可恢复未设置。旧 Demo 双方保留默认敌对关系。独立实体也能单独设置关系。联盟不会自动公开尚未执行的行动计划：仅控制者或确切同阵营的玩家可查看这些计划，可见性仍由服务端过滤。关系不自动禁止攻击或治疗，合法目标继续由动作规则决定。

GM 可设置自定义阵营或将角色设为独立，大厅分配角色不再限制所属阵营。胜负条件支持「仅剩一方或同盟」与「手动结束」；自动判定包含所有参战角色，多个幸存方必须两两同盟才能共同获胜，未设置或中立的不同方不会被自动合并。胜方支持独立实体及多个同盟阵营，完成当前已提交事件后才结算。阵营关系和胜负条件随开局快照保存，重新开局恢复开局设定。

列表只遍历服务端已下发的可见实体，包含角色、场景物与投射物。每个实体使用紧凑单行，主列展示名称与阵营、生命/韧性/专注的资源条及当前/上限数值、提交状态符号、当前动作与执行阶段。名称前不再显示职业头像，资源缺失时显示「—」；条形比例限制在有效范围内，原始数值保持不变。提交、等待、受阻和待决反应用不同形状区分，悬停可查看完整状态。更多信息按需展开，提供其他资源、职业、位置、控制关系、连接和技术标识。默认尺寸用于同时查看不超过 10 个实体的关键信息。点击实体名称只改变本地选择，不提交行动或转移控制权。

全局进度由时间轴展示，实体列表不再重复显示当前 Tick、提交窗口和全局等待状态；列表仅保留每个实体的提交、等待、收招、倒下、动作和待决反应状态，不新增回合计数。缺少行动槽位的实体不会被当作待提交玩家；GM 托管与玩家断线分别显示。窗口支持自动贴边、固定、拖动、缩放、最小化、隐藏和找回；旧布局迁移到 v3 时保留已有位置并补充缺失窗口。
